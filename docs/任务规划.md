# 项目任务规划：具身能力边界与记忆增强

## 一句话目标

让同一个开源模型做同一批机器人任务，逐步给它增加工具、规划和记忆，弄清楚：**模型独自能做到哪里，哪些帮助真正有效，在哪些情况下仍然会失败。**

这里的“具身任务”是让智能体观察场景并操作环境，例如找到物体、抓取、放置，或者在失败后调整动作。最终成绩以仿真器的真实任务判定为准，不能只看模型说“我完成了”。

## 我们想回答的三个问题

1. **能力边界在哪里？** 通用视觉语言模型直接给动作，遇到新物体、新布局、连续多步任务或操作失败时，成功率如何变化？失败主要发生在看错、计划错、动作调用错，还是没有根据反馈纠错？
2. **工具和规划帮了多少？** 给同一个模型查询、机器人原语和分步规划能力后，是否比直接给动作更容易完成任务？代价是多少次调用、多少时间和多少计算资源？
3. **记忆帮了多少，何时反而有害？** 让模型检索以前完成过的任务，是否能更快解决相似但未见过的任务？旧经验不适用时，能否发现错误并改用当前观察和工具结果？

我们**不预设**工具或记忆一定提升成绩。实验应同时记录它们的收益、成本和失败案例。

## 希望最后能说明什么

- 给出一张可复现的能力图谱：简单任务、长程任务、场景变化和意外失败下，各方案的成功率与常见失败原因。
- 用公平的对照实验说明，成绩变化究竟来自模型本身、工具、显式规划还是检索记忆，而不是换了模型、任务或预算。
- 找到值得继续优化的瓶颈。例如，若多数失败来自“抓取后没有核实结果”，下一步应改进反馈与纠错；若主要是找不到正确历史经验，则应改进检索。
- 产出可复用的评测代码、任务清单、运行记录和失败案例，使后续更换 Qwen 模型或 benchmark 时仍可比较。

这些是**预期研究产出，不是已经得到的结论**。

## 实验如何设计

首轮尽量只换一个因素。选定同一个开源模型、同一组任务与随机种子，保证看到的观察、可用的底层机器人动作，以及动作次数和时间上限一致。

| 方案 | 模型得到的帮助 | 要检验的问题 |
| --- | --- | --- |
| A：直接操作 | 当前观察；模型直接决定下一步动作 | 原始能力边界 |
| B：工具调用 | A + 明确的查询与动作工具、执行回执 | 工具是否改善观察与执行 |
| C：规划 + 工具 | B + 子目标与执行后检查 | 长任务是否更稳，失败后能否纠错 |
| D：规划 + 工具 + 记忆 | C + 从训练任务检索的经验 | 历史经验是否提高成功率或降低成本 |

之后再做两种关键对照：只保留最近交互、不检索旧任务；以及提供过时或错误经验，看智能体会不会盲从。闭源模型如需使用，仅作为单独标注的工具或参考组，不承担项目的主要实验结论。

**防止“提前看答案”：** 记忆库只收录训练任务中真实成功、来源可追踪的记录；测试任务及其结果不能写回用于同一轮测试的记忆库。测试需同时覆盖不同随机种子、物体或布局，并记录训练与测试是否共享任务模板。

## 先在哪些 benchmark 上做

1. **LIBERO-PRO：第一站。** 从一小组桌面操作任务开始，比较 A–D 四组。PyRUA-Lean 已提供相关适配路径，适合先把模型、机器人接口、日志和统计流程跑通。建议固定任务清单，每组使用相同的 20–50 个任务与种子组合；这个数量是试运行目标，不是最终统计保证。
2. **RoboDojo-Sim：第二站。** PyRUA-Lean 和 RoboICL 都涉及该基准，适合检查双臂操作、工具编排、示范与交互记忆。其仿真依赖和 GPU 要求更高，等第一站稳定后再做。
3. **RoboTwin 2.0 / RoboCasa365：扩展。** 前者看双臂和场景迁移，后者看更长的复合任务和状态保持。前两站的对照流程可靠后再扩展。

不能直接拿不同论文的公开总分当作本项目的 A–D 对照；模型、动作接口、任务集合和预算可能不同。

## 分阶段任务与验收

| 阶段 | 要做的事 | 完成时应拿得出的证据 |
| --- | --- | --- |
| 0：评测骨架（已完成） | 统一任务/策略接口、动作回执、训练记忆隔离、简单纠错与日志；用合成任务做接口测试 | 测试能复现；明确标注它不是机器人或 VLM 成绩 |
| 1：首个真实任务 | 接入 LIBERO-PRO 原生环境与成功判定；记录任务、种子、观察、动作、回执、模型版本和预算 | 至少一个开源模型实际完成完整评测流程；失败任务也有可读轨迹 |
| 2：能力边界 | 在固定任务集上运行 A、B、C；按任务类型和变化因素分类失败 | 配对结果表、成功率、资源消耗及失败案例 |
| 3：记忆实验 | 建立训练任务 Memory Bank；运行 D、最近历史和错误记忆对照 | 检索来源可追溯；测试集无泄漏；能看到记忆带来的收益或损害 |
| 4：复核与扩展 | 增加种子和任务；给配对结果计算不确定区间；再迁移到 RoboDojo | 可复现的配置与原始记录；不同基准的结论分开报告 |

主要指标是**任务成功率**；同时记录部分进度、失败后的恢复率、动作/工具调用次数、延迟和模型计算成本。先保留每个任务的原始结果，再汇总平均值；样本太少时只报告探索性发现，不宣称普遍提升。

## 当前状态与下一步

仓库已有可运行的合成环境、A/B/D 的确定性占位策略、Memory Bank、OpenAI 兼容文本动作接口和测试。它们用于检查实验流程，不代表 Qwen 或其他模型的具身能力。下一步是搭建可运行 LIBERO-PRO 的 GPU 仿真环境，把原生观察与成功判定接到统一接口，再接入具体 Qwen 模型，补齐 C 组并执行首轮真实配对实验。

技术接口和依赖顺序见 [英文研究计划](research_plan.md)。
