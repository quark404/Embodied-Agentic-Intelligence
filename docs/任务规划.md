# 项目任务规划：RoboDojo 能力差距与 Qwen Agentic RL

## 一句话目标

在**同一 RoboDojo 任务、机器人动作接口与物理预算**下，测出开源 Qwen Agent 与 GPT-6 Astra 等前沿闭源模型之间的差距主要出现在哪些环节，再检验：**只把 Astra 作为少量、受限的规划或诊断工具，能否帮 Qwen 补上其中一部分差距。**在此基础上，研究能否用示范学习和可验证的局部训练，让 Qwen 自己学会判断、纠错及何时求助，减少对闭源工具的依赖。混合组的每一步机器人动作由 Qwen 决定，Astra 工具只给结构化建议，不能直接输出电机命令或宣称任务成功。

这条路线合理，因为它把“谁理解目标、谁处理失败、谁控制机器人”拆开比较。也有边界：即使 Astra 给出正确计划，低层动作仍可能失败；混合方案多用了闭源推理，成功率提高不一定划算。我们不预设混合组一定优于 Qwen。

## 研究问题与预期说明

1. **整体差距在哪些任务上最大？** 在相同观察、动作原语、任务/seed 和原生判定下，比较 Qwen 完整 Agent 与少量任务上的 Astra 完整 Agent 参考组。按 Open、Precision、Long-Horizon、Memory、Generalization 分组，区分看错物体、计划错误、动作调用错误、失败后不纠正和长期状态遗忘。
2. **Astra 规划工具能补多少？** Qwen 执行动作，Astra 只输出带 ID 的子任务计划。若计划更准但抓取等依然失败，差距主要残留在执行端。
3. **Astra 诊断工具能补多少？** 机器人动作回执拒绝时可自动调用一次；已有动作后，Qwen 即使收到“执行成功”的回执，只要观察到任务没有进展，也可显式请求一次诊断。Astra 提供原因和建议，Qwen 决定下一步；量出恢复率、重复错误率和额外代价。
4. **任务级初始图像记忆何时有效？** 每个子任务开始保存原始图像；之后显式按同一 episode 的子任务 ID 回忆。比较有无记忆，并测试旧图像是否会误导。这里没有向量 RAG。RoboICL 的 LIVE 动作轨迹记忆与本项目初始图像记忆是不同变量。
5. **Qwen 能否真正学会，而不只是更会依赖 Astra？** 在不改变机器人接口的前提下，用独立训练数据做示范学习、可验证的局部训练和有限求助策略训练。训练后关闭 Astra 再测原生成功率；只有此时也提高，才能说一部分能力留在 Qwen 本身。离线任务提高不自动等于机器人成功率提高。

这些是**待检验假设，不是现有结论**。最终需给出“哪类任务差距大、哪种受限工具有效、成本多少、剩余失败在哪”的证据，而不是只给一个总成功率。

核心比较为 q_only→hybrid_plan、q_only→hybrid_diagnose、hybrid_plan→hybrid_both、hybrid_both→hybrid_both_memory；少量任务另作 q_only↔astra_reference。**公开论文的 Astra 分数不是本项目配对结果。**

主对照固定 Qwen checkpoint/推理配置、三相机 RGB、机器人公开状态、原语及动作转换、安全守卫、任务/布局/seed、示范数量、物理步数和原生评分。Astra 工具输入限于同条件可见的目标、观察、回执和已完成进度；输出须过 schema 和长度检查。**每 episode 最多一次 Astra 计划、一次 Astra 诊断，合计最多两次闭源调用**；后续若需重新规划，由 Qwen 完成。诊断触发为动作被拒绝后的自动调用，或 Qwen 在已有动作后显式提交 consult；后者可用于“动作执行成功但没有任务进展”的情况。无先前动作的 consult 拒绝，预算用尽后不再调用 Astra。完整记录每次 Astra 调用的角色、触发原因、输入/输出摘要、token、时长、费用与预算余量。无权限组的代码和提示都禁止调用，不能仅文字上关闭。

混合组比 q_only 多了计算资源。主要报告同物理步数/任务时间上限下的原生成功和进度，同时报告 Qwen/Astra 请求数、总延迟、token 与成本，绘制预算—成功率关系。闭源完整 Agent 组单独标注资源差异，不能把“模型差距”与“多花了计算”混为一谈。

| 7：训练后闭环验收 | 在未见 RoboDojo 任务/布局上对比训练前后 Qwen、训练后有/无 Astra 和小样本完整 Astra 参照 | 原生配对成功率、进度、专家撤除后的自主成功率、调用成本与剩余差距 |

## 将 Agentic RL 合并为第二阶段

现有 `q_only`、`hybrid_*` 和 `astra_reference` 是**未训练、同接口的差距诊断基线**，保持原条件名和预算不变。训练后的 Qwen 必须使用新的 checkpoint 和条件名，至少比较：原始 Qwen 无专家、SFT 后 Qwen 无专家、局部训练后 Qwen 无专家，以及**同一个经过专家求助策略训练的 checkpoint**在 Astra 开启和关闭时的表现；少量任务保留完整 Astra 参考。这样分别回答“模型自己进步多少”“专家还能补多少”“会不会离开专家就失效”。不得把训练增益写成原有 harness 组件的增益。

最小可执行训练顺序是：先从独立训练集导出轨迹与人工/规则核验标签，再做示范学习；随后只在有明确标准答案的规划格式、工具参数合法性、执行回执理解、正确子任务图像 ID 和求助决策上尝试可验证的局部训练；最后才考虑在现成 RoboDojo 环境里做少量闭环策略更新。静态图像和旧轨迹没有“尚未执行的新动作的真实后果”，因此不能用离线代理奖励代替物理成功。Qwen 可以决定继续操作、回忆或求助，**任务最终成功仍只能由 RoboDojo 判定**。

训练、验证和最终测试需按任务及布局隔离，冻结 seed；测试轨迹、未来帧和官方隐藏奖励不得进入教师提示、检索或策略输入。当前 Astra 工具仅限一次规划与一次诊断。空间定位、状态核验等更细粒度专家是**后续候选实验**，如果启用必须另建条件矩阵，不能悄悄放进上述六组。具体数据字段、比较矩阵、论文借鉴与适用边界见[Agentic RL 扩展路线](../research/benchmarks/agentic_rl_roadmap.md)。

Memory 的子任务进度有一个重要限制：RoboDojo 通常只给原生 episode 成功/进度，不提供通用的子任务完成谓词。Harness 可让策略在当前子任务已有一次成功动作回执后显式提交“进入下一子任务”，并记录为**未经环境验证的计划进度**，以便在新的子任务开始时保存图像；它绝不能变成原生成功信号。真正的任务成功始终来自 RoboDojo。

汇总时分别展示所有原生计分和可用于模型比较的 episode。缺失 harness 轨迹、未完成的 native run，以及模型服务或仿真故障，从主比较分母剔除并列出原因；模型返回不合法 JSON 或违反动作决策协议则算模型失败。每个条件都显示有效分母与排除数，避免把运行故障误判为具身能力差距。美元费用需要预先填入模型单价；未填单价时只报告调用、token 与时长，不伪造金额。

若 Qwen 在简单任务持续无有效动作或原生成功，先检查相机新鲜度、14 维动作顺序、坐标与单位、控制转换、安全守卫、提示/解析和预算。必要时可让所有对照组共用同一训练型 VLA 作为低层执行工具，再研究 Qwen 规划与 Astra 建议；这种条件须标为“Qwen 上层 Agent + VLA executor”，不能声称 Qwen 独立完成底层操作。首轮 20–50 个任务/seed episode 是工程筛选，不是稳定榜单成绩。

## 参考和当前边界

[RoboICL](https://github.com/Mosi-AI/RoboICL) 提供双臂动作、示范与 LIVE 交互记忆的设计参考；[PyRUA-Lean](https://github.com/DAGroup-PKU/PyRUA-Lean) 提供 Python 原语与反馈参考；[HexaShell](https://github.com/HexaFuture/HexaShell) 提供薄工具接口和失败后修工具参考。它们在 RoboDojo 的主要公开 Agent 成绩使用 GPT-6 Astra，不能当作 Qwen 基线。Qwen/RoboDojo 证据见 [现有调研](../research/benchmarks/robodojo_qwen.md)，本项目的完整分组与验证协议见 [混合实验说明](../research/benchmarks/mixed_agent_robodojo.md)。

环境选择须在实验前冻结：RoboICL 风格的 ee_delta 动作及原生 IK 连续性保护依赖 Mosi-AI 固定的 RoboDojo fork `00ef04cd245bfa76e6f1e0bd8383c82f7964f942`；RoboDojo 官方 main `f57e1633ffed59761bc8e568cfe7530c4b33381c` 缺少 `src.eval_client.ik_continuity`。若走官方 main，应选择其 joint 动作模式。所有对照组必须使用同一代码版本和动作模式，不能跨模式比较后归因于模型。

当前仓库的合成测试只能证明控制流，尚未验证真实 Qwen、Astra 端点、GPU 仿真或官方 RoboDojo 评分。真实分数须等相应环境运行后填写。
