# 跨服务器开发与部署

适用范围：Qwen3.5 Harness 开发、隔离推理、RoboDojo 源码接入和 AIDI 单卡预检。当前不包含已验收的 Isaac 安装镜像、真实具身成绩或 RL 训练环境。

## 1. 目录与职责

| 目录 | 职责 | 默认是否启动服务/申请资源 |
|---|---|---|
| `embodied_agentic/` | 模型接口、Harness、动作守卫、原生评分适配 | 否 |
| `integrations/xpolicylab/` | 仿真侧适配入口 | 仅显式执行评测脚本时 |
| `scripts/` | 模型下载、推理启动、接口检查、固定源码准备 | 各入口独立；下载和启动需主动执行 |
| `cluster_eval/` | 私有凭据、只读队列查询、冻结准备、受限提交与状态 | 只有 `submit_preflight --execute` 提交 |
| `configs/` | 无凭据模板和上游 revision 锁定 | 否 |
| `requirements/` | 按角色分离的依赖，不是一个通用环境 | 否 |
| `tests/` | CPU 契约与安全边界测试 | 不访问真实模型、不申请 GPU |
| `runs/` | 本机日志、冻结包、回执和诊断文件，Git 忽略 | 不随 GitHub 同步 |

所有 `python -m ...` 命令均从仓库根目录运行。`scripts` 和 `cluster_eval` 是显式 Python 包，避免其他环境里同名包覆盖本项目入口。不要把多个服务器的绝对路径写进公共模板。

## 2. 最小开发环境：不需要 GPU 或 AIDI

首次在**新 checkout** 中创建项目自己的环境，不修改系统 Python、既有 Conda 环境或其他人的虚拟环境：

```bash
git clone --branch research/agentic-rl-20261029 \
  https://github.com/quark404/Embodied-Agentic-Intelligence.git
cd Embodied-Agentic-Intelligence
python3.11 -m venv .venv-dev
.venv-dev/bin/python -m pip install -r requirements/dev.txt
.venv-dev/bin/python -B -m unittest discover -s tests -v
.venv-dev/bin/python -B -m embodied_agentic.experiment \
  --config configs/robodojo_qwen35_27b.local.example.json --condition q_only
```

如 `.venv-dev` 已存在，先核实归属再复用，不覆盖未知环境。`requirements/dev.txt` 固定已在本机通过测试的 NumPy/Pillow 版本，**不能拿它给 Isaac 环境装依赖**。测试与最后一条配置校验都不启动机器人，也不调用收费 API。

更新代码使用当前研究分支；已有未提交修改时先检查 `git status`，不要使用强制 reset/clean。复现时记录 `git rev-parse HEAD`，不要仅记录可移动的分支名。

## 3. 四个角色分别配置

| 角色 | 环境与入口 | 必须由当前服务器重新确认的内容 |
|---|---|---|
| CPU 开发 | Python 3.11 + `requirements/dev.txt` | 新环境目录与测试结果 |
| Qwen 推理 | `requirements/qwen35-serving.txt`；`scripts/serve_qwen35.sh` | GPU 分配、显存、端口、缓存路径、驱动 |
| AIDI 提交 | `requirements/aidi-submit.txt`；`cluster_eval` | 内部包源、私有 token、队列权限、本用户 JFS 路径 |
| RoboDojo 仿真 | 目标 Python 3.11 / Isaac Sim 5.1.0 | RT 硬件、图形驱动注入、RGB 渲染、上游依赖冲突、资产 |

### 推理服务器

按 [Qwen 推理环境](Qwen3.5推理环境.md)新建独立环境并下载固定权重。启动时必须明确给出已经分配给自己的 GPU：

```bash
export QWEN_ENV=/path/to/your/qwen35-vllm
export QWEN_GPU=0
export QWEN_PORT=18000
bash scripts/serve_qwen35.sh
```

这里的 `0` 只是示例，不是自动选卡建议。启动脚本不再默认使用原服务器的 GPU6；若设置了 `CUDA_VISIBLE_DEVICES`，选卡还必须属于其分配范围。已有 UUID 掩码无法与此数字编号预设安全对应时会拒绝启动，不绕过调度分配。空闲检查不是资源预约，需要先通过管理员/调度器确认。

这是单卡 BF16/32K 预设，已在 H20 上做接口验证；不是适用于任意显存容量或多卡拓扑的通用启动器。27B 原始权重约 51.75 GiB，不能照搬到单张 32 GiB 的 5090。脚本变更不影响已经运行的推理进程。

### 提交服务器

优先使用新的 Python 3.11 SDK 环境，安装 `requirements/aidi-submit.txt` 需要获授权的内部包源；当前独立安装尚未验证。已有 SDK 可以通过其 Python 绝对路径只读调用，**不意味着可以向那个环境继续装包**。

```bash
export AIDI_PYTHON=/path/to/your/aidi-submit/bin/python
"$AIDI_PYTHON" -B -m cluster_eval.credentials
"$AIDI_PYTHON" -B -m cluster_eval.query_queue \
  --output "runs/cluster_eval/queue-$(date +%Y%m%d-%H%M%S).json"
```

凭据初始化只在新服务器首次执行，已有私有文件时拒绝覆盖；token 从隐藏提示输入，不通过 Git、命令行参数或聊天传递。完整提交步骤与安全开关见 [AIDI 文档](../cluster_eval/README.md)。公共配置保留指定队列；不要仅修改队列名称就假定其他项目具有相同权限或挂载。

### 仿真服务器：先做预检，不执行上游一键安装

固定源码准备只下载小型源码、链接本仓库 policy，不安装 Isaac、不下载资产，也不修改已有 checkout：

```bash
.venv-dev/bin/python -B -m scripts.prepare_robodojo_sources \
  runs/upstream/RoboDojo
.venv-dev/bin/python -B -m scripts.check_robodojo \
  --robodojo-root runs/upstream/RoboDojo \
  --output "runs/preflight-$(date +%Y%m%d-%H%M%S).json"
```

第二条命令未提供仿真 Python/GPU，返回 `2` 表示配置不完整，是正常的预检结果。待环境与分配准备好，再显式提供 `--sim-python /path/to/isaac/bin/python --sim-gpu <分配编号>`。退出码 `0` 也只代表静态/元数据检查通过：`native_ready` 仍为 false，需要真实相机与任务验收。不能用库存在、设备型号或合成测试替代 RGB 渲染。

`configs/robodojo_versions.json` 记录实际 gitlink 对应的上游版本；不要更新到移动的 main，也不要为绕过 IK 守卫切换控制模式。XPolicyLab WebSocket 与 Isaac 安装脚本的版本冲突尚待独立环境验证。H20 不用于该 Isaac 渲染路径；5090 集群预检任务仍需实际启动并通过后续渲染检查。

## 4. 两台机器之间如何连接

优先结构：H20 服务器运行 Qwen；支持 RTX 渲染的机器运行 Harness、RoboDojo 和本地 XPolicyLab reset 桥。每个机器人动作仍由 Qwen 决定，不把 XPolicyLab 占位服务误当成主模型。

Qwen 只监听推理机器的 `127.0.0.1`。经授权的 SSH 连接可在**仿真机器**前台建立隧道：

```bash
ssh -N -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 \
  -L 127.0.0.1:18000:127.0.0.1:18000 "$INFERENCE_SSH_TARGET"
```

随后仿真机器的配置可继续指向 `http://127.0.0.1:18000/v1`。端口冲突时换端口并同时修改私有配置；不要停止别人占用端口的进程。AIDI 作业内能否连接开发机尚未验证，不能假定这个命令在集群也能直接使用。不要上传个人 SSH 私钥、关闭主机校验或把无认证模型接口开放到公网。

在隧道建立后，从具备 Pillow 的 CPU 环境运行 `python -B -m scripts.check_qwen35` 才会实际调用 Qwen 做接口检查；它不执行机器人动作。闭源端点未配置时只使用 `q_only`。

## 5. 多服务器协作与发布边界

- Git 同步：源码、无凭据模板、版本锁和说明；不包含 `.venv*`、`.env*`、`runs/`、私有配置/日志、模型和资产。不要使用 `git add -f` 绕过这些规则。
- 每台机器重新准备自己的绝对路径和新 run ID，**不要直接复制并执行另一台机器的提交配置**。原配置带路径、摘要和提交锁，不是通用模板。
- 本机 `runs/` 不随仓库下载；跨机器查看已提交作业，可以用私有配置初始化后的只读入口：`python -B -m cluster_eval.aidi_cli manager get --job-id <已知job_id> --output text`。不要把缺少本机回执理解成没有提交过。
- 已提交源码包保持冻结。代码更新只影响之后准备的新包，不修改正在排队或运行的作业；不要删 attempt 文件来重复提交。
- 结果写到本用户 JFS run 目录。其他机器必须实际验证同一挂载和访问权限；本机能看到 `/jfs-public` 不证明另一集群能看到同一内容。
- 失败时保留配置摘要、日志、原生结果与分母；不把网络/仿真故障当作模型失败，也不把预检通过称作任务成功。
- 运行环境、权重和资产都按角色独立管理；只清理自己明确创建的目录，不清理共享缓存或既有训练环境。
