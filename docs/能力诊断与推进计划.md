# 两阶段研究：闭源补强能力诊断 → 低成本 Agentic RL

对齐日期：2026-10-29。本文是后续工作安排，不是已完成的实验结果。首轮六组定义仍以[混合 Agent 协议](../research/benchmarks/mixed_agent_robodojo.md)为准；训练细节见[Agentic RL 路线](../research/benchmarks/agentic_rl_roadmap.md)。

## 1. 两个研究重点与当前边界

1. **先回答哪些能力最值得由闭源模型补强。** 不只比较总成功率，还要区分开闭源能力差距、单项专家建议带来的闭环收益及成本。这是第一阶段独立的研究产出，不只是为训练收集数据。
2. **再回答如何用低成本 Agentic RL 学到这些能力。** 依据第一阶段证据选择目标，在可执行轻量环境中直接进行多轮 RL，最后用独立 RoboDojo 闭环验收能力迁移与成功率。

**当前路线不包含 SFT，也不把 SFT 作为 RL 的前置条件或首批必要对照。** 主线完成后是否补充 SFT，另行决定；现在不准备其训练管线。我们不训练 VLA，现有 Qwen 主控与受限专家的分工保持不变。

当前已存在 Harness、六组条件、环境桥接和合成契约测试；2026-10-29 已补充[本地 Qwen3.5-27B 真实端点检查](Qwen3.5推理环境.md)，验证文本、三图像、工具调用与 Harness 解析。Astra 端点、原生仿真评测、能力差距和 RL 效果仍待验证。`synthetic.py` 是控制流演示，不代表下面的轻量训练环境已经建好。

## 2. 先诊断哪些能力，不预先认定瓶颈

| 候选能力 | 需要观察的错误 | 闭源可提供的单项帮助 | 专项检查与闭环证据 |
| --- | --- | --- | --- |
| 视觉定位与空间关系 | 对象、相对位置或目标指代理解错误 | 基于相同图像给对象与关系证据，不发动作命令 | 独立标注的定位/关系正确率；补强后目标选择与任务结果 |
| 状态跟踪与历史记忆 | 忘记已做步骤，把旧图像当成当前状态 | 在相同可见历史中指出相关证据及时间属性 | 历史检索、状态一致性；补强后的重复操作与长程成功率 |
| 任务分解与约束规划 | 顺序不当、漏前置条件、子目标冲突 | 给子目标顺序与约束，不给低层动作 | 计划约束满足率；执行后的原生进度和成功率 |
| 执行结果核验 | 把“调用成功”误判为“目标完成”，未发现停滞 | 指出可见证据、状态疑点与应检查项，不给官方成功 verdict | 有可信标签时的误判率、漏检率；无效继续次数和闭环结果 |
| 失败诊断与恢复 | 错误原因判断不准，重复无效动作或耗尽预算 | 给失败解释和恢复方向，具体动作仍由 Qwen 决定 | 剩余预算内的恢复成功率、额外动作及总任务成功率 |
| 工具约束与执行可行性 | 参数/坐标/控制范围理解错误，合法动作也无法操作 | 解释违反的约束，不替 Qwen 生成机器人命令 | 协议错误、动作拒绝与实际执行率；区分接口问题与模型问题 |

此表是候选诊断维度，不是已实现的六种专家工具。先用现有规划、诊断和记忆对照粗筛，再为有证据的维度定义细粒度工具。是否求助作为决策日志记录；学习求助路由放到后续，不替代能力诊断。

状态记忆需要区分“根本没提供证据”和“给了证据仍理解错”。比较开闭源模型本身时给相同历史；比较记忆工具时则单独标注信息可用性这一干预。动作不可执行时先检查接口，不能把其失败全归为规划或推理不足。

## 3. 如何让“这部分能力有用”的结论可信

### 3.1 三层证据，不用失败标签代替因果判断

1. **同接口整体差距：** 用 `q_only` 与小样本 `astra_reference`，固定模型输入、任务/布局/seed、执行器、守卫、物理预算与评分器。它只说明整体差距，不说明哪种能力造成差距。
2. **单项工具的增量：** 现有六组回答规划、诊断和记忆帮助是否有效。它们是功能级干预，规划文本可能同时包含空间和恢复信息，不能自动解释成纯粹的单能力提升。
3. **能力级专项干预：** 对粗筛后的维度建立独立版本 `diagnostic_v2`，限制输入、输出字段和触发点；把无建议、Qwen 自建议、闭源单项建议作对照，保持同一 Qwen 动作端。新工具和新配额不能偷偷混进原六组。

在 `diagnostic_v2` 中预先固定可由公开观察/回执判断的触发规则，不能事后只挑闭源救回的失败。固定前缀可以用于比较专项回答，但只有实际续跑才能说明对成功率有帮助。环境支持并验证完整状态恢复时才做同前缀分支续跑，同时保存机器人/物体状态、随机状态、历史、记忆和剩余预算；否则从相同任务/布局/seed 的 reset 开始配对运行，并明确不是严格的同状态反事实。日志回放不能提供未执行动作的真实后果。

### 3.2 必须固定或单独报告的混杂因素

- **计算与信息：** 同样的物理预算不等于同样的推理成本。增加 Qwen 自建议对照，匹配调用机会与输出上限，并报告实际 token、延迟、费用；另做预设总预算下的成功率比较。等 token 不声称等算力或等价格。
- **建议质量：** 抽样人工/规则检查建议是否正确、是否越过能力范围。自动 schema 检查只能限制结构，不能证明文本没有混入其他能力；无法拆开的建议标为组合干预。
- **评分与泄漏：** 专家不看隐藏评分、未来帧或测试答案。专项真值只用于离线核验，原生成功由环境判定。子任务 `advance` 和工具 `ok=true` 均不等于目标已完成。
- **数据与选择：** 在诊断之前划定开发与锁定测试。开发侧再分探索和独立确认子集，用于发现并复核瓶颈；若确认结果用于选择训练目标，它就不是最终测试。锁定测试只验收冻结假设，不能又用于选择训练能力、奖励或工具。任务外推与布局外推分别报告。
- **统计与异常：** 同任务/布局/seed 配对，报告每项分母、配对差与不确定区间；多次采样按 episode/布局聚合，不能把同轨迹的多个动作当成独立成功样本。探索多个维度后需独立确认，不能挑最高增益当稳定结论。服务故障、模型协议错误与正常任务失败分别统计。

## 4. 第一阶段必须交付什么

交付一张“闭源补强能力地图”，每个候选能力至少记录：

| 证据 | 要回答的问题 |
| --- | --- |
| 错误频率与暴露次数 | Qwen 多常遇到该能力需求，多常出错？同一失败允许多标签和不确定标签 |
| 同输入开闭源专项差距 | 闭源在同样证据下是否确实判断得更好？ |
| 单项干预的配对成功率差 | 只增加这一项建议，是否带来实际任务增益，而非仅答案更漂亮？ |
| 相对 Qwen 自建议的增量 | 收益是否超过多一次开源推理带来的改善？ |
| 救回与损害 | 基线失败中救回多少、基线成功中破坏多少？同时保留全体配对成功率差 |
| 成本与剩余失败 | 每 episode 多花多少调用、时间和费用；正确建议是否仍卡在执行层？ |

先按“常见错误 + 有专项差距 + 单项补强可改善闭环”筛选，再比较成功率—成本权衡，不先把不同量纲加成一个任意总分。最终挑出证据最充分的一至两个训练目标；若差距不清楚或建议无效，就继续排查信息、接口与实验功效，不强行宣布验证/恢复是瓶颈。

这里的“最需要闭源”只指**所测模型、接口与预算下闭源补强价值最高**，不是证明开源永远学不会。第一阶段即使暂不开展 RL，也应产出可复核的对照、能力地图与边界结论。

## 5. 后续进入低成本 Agentic RL 的条件

每个被选能力先写一份环境规格：可见观察、隐藏状态、可调用动作、状态转移、失败机制、终止、预算与可验证奖励，并说明哪些真实任务后果不受支持。静态图像/日志可用于诊断与构造初始条件，但不能由 LLM 随意编造新动作的物理后果。

- **若瓶颈是核验/恢复：** 构建调用成功但目标未完成、证据过时、部分执行失败等状态变化任务，要求策略主动检查、补救和在剩余预算内完成任务。
- **若瓶颈是规划/记忆：** 构建有前置条件、部分观测、延迟信息需求和可验证目标的多轮任务，避免只做计划排序或图像 ID 选择题。
- **若瓶颈是视觉/低层执行：** 先确认轻量环境能否保留所需视觉证据与动作约束；不能把纯文本环境的收益直接外推为定位、接触或动力学能力。

随后从同一原始 Qwen checkpoint **直接多轮 RL**，比较未训练、单能力训练、联合训练；工具、执行器与测试条件保持一致。核心奖励来自环境可验证的任务结果，格式/错误调用约束是辅助项，不能靠刷格式分替代完成任务。若初始成功稀疏，先检查接口并设计课程、任务难度和奖励，记录引导成本，不自动转成 SFT 路线。

低成本研究先测耗时拆分，再一次只改变一个因素：环境执行、模型生成、工具等待、重试、训练更新。比较均匀采样与按价值/耗时采样、完整展开与合理的短任务/中止策略、基础信用分配与候选改进。所有减少 rollout 的策略都需检查截断偏差、难例覆盖和最终成功率，不能只报告吞吐。

验收同时看：**相同总预算的成功率、达到预设开发集目标的总成本、独立 RoboDojo 原生成功率，以及专家关闭后的自主能力**。目标未达到时标为未达到，不外推所需时间。大规模采样放在轻量环境；RoboDojo 主要用于诊断和独立验收。若另加少量物理 RL，必须单列“轻量 RL”与“轻量 RL + 物理 RL”，不能把后者收益归给前者。

## 6. 接下来按什么顺序做

| 顺序 | 具体工作 | 可检查的交付物与门槛 |
| --- | --- | --- |
| 0：协议与日志 | 固定模型/checkpoint、服务、上游版本、动作模式、预算、数据划分；定义错误标签和能力指标 | 冻结配置、任务划分、日志字段与失败分类规范；新增字段先审计现有实现是否已记录 |
| 1：真实单轮接通 | 检查现有环境和服务；先在 `general_pickup` 跑 Qwen，再跑小样本闭源参照 | 当前图像、有效动作、回执、原生结果能串起来；工程故障与模型失败可区分 |
| 2：未训练粗筛 | 在开发集按现六组进行配对；检查规划、诊断、记忆以及低层执行的影响 | 配对结果、失败轨迹和成本拆分；20–50 episode 仅作工程/探索先导 |
| 3：能力级确认 | 根据粗筛结果选择专项 probe 与 `diagnostic_v2` 单项专家、自建议对照 | 冻结干预范围和触发规则；在独立确认集复核闭环增益，形成能力地图 |
| 4：训练目标决策 | 选一至两个有证据且可用轻量环境验证的能力 | 环境规格、训练/验证划分、奖励依据、迁移边界；此时再确定 RL 方法 |
| 5：直接 RL 与成本实验 | 搭环境、接 RL、做单能力/联合和效率消融 | 固定 checkpoint、完整成本账本、达到目标的成本与同预算性能 |
| 6：独立具身验收 | 冻结方案，在未见任务/布局运行训练前后及专家开/关 | 原生配对成功率、残留能力短板和自主收益；锁定测试不回灌训练 |

**现在优先推进 0、1，并准备 2 的记录规范；不先堆 RL 算法，不先做 SFT，也不预先确定要训练哪种能力。** 上述交付物是待开展工作，不意味着代码和真实实验已经完成。
