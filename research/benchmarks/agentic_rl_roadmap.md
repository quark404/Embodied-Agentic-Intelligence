# 从闭源补强能力诊断到低成本 Qwen Agentic RL

初版日期：2026-10-28；路线对齐：2026-10-29。本文整合用户提供的《RoboICL 式 Harness → Qwen 具身 Agentic RL》及后续六项论文借鉴建议。**本次没有核读这些新增论文的正文**；下表对论文作用的归纳是待核查的研究线索，不是论文结果复现。既有 [RoboDojo/Qwen 证据核查](robodojo_qwen.md)与[未训练混合 Agent 协议](mixed_agent_robodojo.md)仍分别负责公开证据和首轮实验定义；[能力诊断与推进计划](../../docs/能力诊断与推进计划.md)规定第一阶段的能力地图和进入训练的门槛。

## 核心判断

两个研究重点按顺序推进：**先证明哪些能力最值得闭源模型补强，再研究如何以低成本 Agentic RL 学到这些能力，最后撤除专家验收**。第一阶段需独立交付能力地图、单项建议的闭环增益与成本，不只是为 RL 收集轨迹。当前六组保持为冻结的未训练基线；细粒度能力干预另建诊断版本，训练后的 Qwen 另开实验组，才能区分 harness 帮助、模型学习和新增闭源计算三种来源。

**当前不考虑 SFT，也不把它作为 RL 的前置条件或必要对照；主线完成后是否补充再议。** 第二阶段从原始 Qwen checkpoint 直接多轮 RL。选哪些能力由第一阶段决定，不能因为已有验证/恢复环境的设想就先宣布它们最重要。

“不新建物理仿真”与本项目使用 RoboDojo 并不冲突：合法记录数据与静态图像用于诊断、环境设计和奖励核查；大量训练 rollout 放在有状态变化的可执行轻量环境，而不是把静态 QA 当作多轮交互。最终仍要在**独立的 RoboDojo 闭环 episode**验证具身成功。旧轨迹只能告诉我们已发生动作的后果，不能给一个未执行的新动作提供真实后果。闭源模型的判断也不能取代原生评分。

主模型应承担目标管理、选择当前证据、决定动作与是否求助、解释回执和决定下一步流程；Astra 只提供预算内的认知建议。Qwen 可以判断是否继续、回忆或请求建议，**官方任务成功始终由 RoboDojo 判定**。若低层动作始终不可执行，后续可让所有组共用一个冻结的 VLA executor，但结论须标为上层 Agent 的学习，不能称为通用 Qwen 独立操作能力。

## 希望证明什么，如何区分结论

| 待验证问题 | 必要对照 | 可以得出的结论 |
| --- | --- | --- |
| 开闭源差距出现在哪 | 当前 `q_only` 对同接口小样本 `astra_reference`；按任务/失败类型分层 | 未训练 Agent 的同接口差距及其主要表现；不能直接套用其他论文分数 |
| 少量专家是否有用 | 当前 `q_only` 对 `hybrid_plan`、`hybrid_diagnose`、`hybrid_both` | 规划/诊断工具在冻结 Qwen 上的增量，同时报告闭源调用成本 |
| 哪些能力最值得闭源补强 | 独立诊断版本的同输入专项检查、无建议/Qwen 自建议/闭源单项建议，加实际配对续跑 | 能力级补强的证据、成本和适用范围；六组功能对照本身不足以证明纯单能力归因 |
| Qwen 是否学会自主解决 | 原始 Qwen、直接 RL 单能力与联合训练 Qwen，**都关闭 Astra** | 模型本体的增量；轻量环境结果仍需具身迁移验证 |
| 是否只是更会求助 | 同一训练后 checkpoint 在专家关闭、固定可用、学习路由三种模式下比较 | 求助策略在同等调用上限下的增量，以及撤除专家后的保留能力 |
| 是否真正降低训练成本 | 同模型/环境/奖励的基础多轮 RL 与效率改进；同预算性能及达到预设开发集目标的总成本 | 环境、采样、信用分配等各自贡献；只省更新计算不能称为省去已执行 rollout |
| 训练能否迁移到具身任务 | 未见任务/布局/seed 的独立 RoboDojo 原生评分 | 才能声称机器人闭环成功率或进度提高 |

模型训练产生新的条件名，例如 `qwen_direct_rl_single_no_expert`、`qwen_direct_rl_joint_no_expert`；如后续研究求助路由，另设 `qwen_router_rl_budget2` 和 `qwen_router_rl_expert_off`。名称在实现时随 checkpoint 与训练方案冻结。专家开/关对照必须使用**同一个训练后 checkpoint**；原始、单能力与联合训练则从同一原始 checkpoint 开始并匹配训练预算。未训练六组与训练后组使用相同评测任务、观察、动作接口、安全守卫及物理预算；训练数据与资源另报。

开始收集训练标签前就划定开发、验证和锁定测试数据，并分别设计两种外推：**任务外推**要求测试 task ID 不出现在训练中；**布局外推**允许同一任务，但测试 layout ID 与 seed/episode 均不进入训练。第一阶段可以另报官方全任务成绩，但第二阶段不得依据锁定测试的失败案例选择训练样本、奖励权重或新增工具；若锁定集已被用于方案迭代，应另选未使用的布局/seed 并降低“未见任务”结论的范围。仅 seed 未见不能称任务泛化。

## 执行顺序与进入下一步的门槛

| 阶段 | 工作与产物 | 进入下一步的条件 |
| --- | --- | --- |
| A. 闭源补强能力诊断 | 先接通原生环境，在开发集运行现六组；再按证据做独立能力级干预、自建议对照与确认实验 | 有效动作与 native score 可用；形成能力地图，不把零成功直接归为某种能力差距 |
| B. 目标与环境规格 | 选一至两个有闭环补强证据的能力；用独立训练划分的公开轨迹定义观察、动作、状态转移、失败、预算与奖励 | 训练/验证/最终测试隔离；奖励可独立核验，明确轻量环境不能覆盖的物理后果 |
| C. 可执行轻量环境 | 实现多轮状态变化、部分观测、检查与失败分支；建立确定性契约测试与成本日志，不仅做静态选择题 | 策略动作确实影响后续状态；可复现且无隐藏评分/未来信息泄漏；未训练 Qwen 可产生有效交互 |
| D. 直接多轮 RL | 从原始 Qwen checkpoint 训练；比较未训练、单能力、联合能力，工具与执行器不变；初期不加入学习路由 | 报告轻量留出环境的任务成功、能力指标及成本；格式奖励不能代替完成任务，尚不称具身提升 |
| E. 成本与算法消融 | 先测模型生成、环境、工具等待与更新耗时，再比较采样分配、信用分配、有效早停等；按需独立研究专家路由 | 同预算成功率与达到预设目标的总成本；逐项改变因素，检查截断偏差、难例覆盖、历史/预算/策略版本匹配 |
| F. 独立验收 | 冻结 checkpoint、提示、工具、专家预算和任务清单；在未见任务/布局上运行训练前后、专家开/关与小样本完整 Astra 参照 | 报告原生成功/进度、专家撤除、自主解决率、调用频率、全流程成本及失败分类；不从开发集挑一次最好成绩当结论 |

A 的环境接线与全流程的数据/日志规范可以同时准备，但 B 的能力选择必须等待 A 的证据。**A 是独立研究产出，D–E 的具身迁移结论必须由 F 验证。** 若只有静态数据，只报告相应专项诊断，不称多轮 RL 或未运行的 RoboDojo 成功率。若后续增加少量物理 RL，另设“轻量 RL + 物理 RL”条件，不能将其增益归给纯轻量训练。

论文线索按诊断结果选择，不先锁定训练能力。带状态变化的任务构建和独立测试分别服务 C、F；预算内恢复仅在 A 支持该目标时进入 B–D。ConCal 式后验归因与 AdaRoll-GRPO/FastRL 式采样优化以足量轨迹和实测瓶颈为前提，作为 E 的候选对照；AgentBaton 式交接仅在能力补强和固定配额基线清楚后研究，不修改第一阶段六组。

## 首批可验证任务与奖励边界

首批离线样本来自当前 harness 的公开观察及回执，按 episode 保存 `task_id`、`layout_id`、`seed`、数据划分、模型/checkpoint、图像哈希与相机、子任务 ID、计划、动作工具和参数、动作合法/拒绝回执、Astra 调用原因及 token、原生终局结果。原生 hidden reward 只可在 episode 结束后用于训练划分的监督标签或分析，不能泄漏给在线策略。测试 episode 不得进入教师提示、Memory Bank、训练奖励或数据选择。

奖励必须来自独立可检查的结果。以轻量环境的终局任务完成为核心，按需要加入经验证的过程信号、无效调用和调用成本惩罚；权重在验证集定好，不根据最终测试成绩回调。JSON/schema、控制范围、图像归属和回执分类可作辅助约束，不能只靠格式奖励取得高分。**教师文本偏好不等于客观可验证奖励**；空间定位与“当前任务是否完成”若无可信标注，先做人工审查/校准，不直接制造 RL 真值。轻量工具任务需真的改变状态，才能训练结果核验与失败恢复；它仍不能模拟抓取接触、碰撞或物体动力学。恢复标签应比较在剩余预算内“继续、重试、换计划”各自的可验证结果；RoboDojo 若没有安全回滚接口，“回退”只能是可执行的补救动作或新 episode，不能假设物理状态可撤销。

若使用已有 rollout 的最终结果给中间决策分配信用，只能作为**训练时的后验信号**，不能把未来观察放进在线策略输入；不同历史、剩余步数、专家配额和策略版本的节点不能简单共享同一个优势估计。先用可验证的局部标签建立基线，再在有足够完整轨迹时比较这种信用分配是否带来额外收益。

闭源专家第一轮仍是当前代码中的**一次计划 + 一次诊断**。上传方案建议的空间定位、局部规划、状态核验是有价值的候选能力拆分，但必须先定义输入证据、结构化输出、可拒答和外部验证标准；任何新增工具都另开版本化矩阵，与原有条件分开汇报。专家不得看未来观察、测试答案或 RoboDojo 隐藏评分，不得向动作执行器发送命令，也不得把自己的“成功”说法覆盖环境 verdict。

## 全流程成本与报告规则

从诊断数据获取/标注、专家调用、环境构建、图像处理、模型 RL、工具执行、失败重试，到最后 RoboDojo rollout，都记录资源用量；区分环境开发开销、一次训练成本与每个评测 episode 的增量成本。训练阶段可按任务价值与实际耗时动态分配采样，**评测阶段仍固定各组的任务和物理预算**。生成后再丢弃轨迹只能省去后续训练计算，不能把已经发生的模型调用或仿真时间算作节省。模型调用日志保留输入/输出 token、延迟、成功/错误和单位价格是否已知；缺失价格标记未知，不能当作零。核心比较是**同总预算的成功率、达到预设开发集目标的总成本、无专家自主成功率与独立原生成功率**；未达目标明确标记，不推算不存在的达标时间。并列报告 GPU 时、墙钟时间、闭源调用和可核算费用，不把不同单位强加成一个数字，也不遗漏开发检查与失败实验成本。
