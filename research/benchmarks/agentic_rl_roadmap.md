# 从 RoboDojo 差距诊断到 Qwen 具身 Agentic RL

规划日期：2026-10-28。本文把用户提供的《RoboICL 式 Harness → Qwen 具身 Agentic RL》并入当前项目。**本轮没有重新读取或核验其中的论文正文**；下表对论文作用的归纳是待核查的研究线索，不是论文结果复现。既有 [RoboDojo/Qwen 证据核查](robodojo_qwen.md)与[未训练混合 Agent 协议](mixed_agent_robodojo.md)仍分别负责公开证据和首轮实验定义。

## 核心判断

上传方案值得吸收的是“**先定位差距，再训练 Qwen，最后撤除专家验收**”。当前代码实现的六组条件应保持为**冻结的未训练基线**，不能因为加入训练而重命名、换动作原语或调整 Astra 上限。训练后的 Qwen 另开实验组，才能区分 harness 帮助、模型学习和新增闭源计算三种来源。

“不新建物理仿真”与本项目使用 RoboDojo 并不冲突：前期可用合法记录数据、静态图像和轻量工具状态机减少训练时的物理 rollout，最终仍要在**独立的 RoboDojo 闭环 episode**验证具身成功。旧轨迹只能告诉我们已发生动作的后果，不能给一个未执行的新动作提供真实后果。闭源模型的判断也不能取代原生评分。

主模型应承担目标管理、选择当前证据、决定动作与是否求助、解释回执和决定下一步流程；Astra 只提供预算内的认知建议。Qwen 可以判断是否继续、回忆或请求建议，**官方任务成功始终由 RoboDojo 判定**。若低层动作始终不可执行，后续可让所有组共用一个冻结的 VLA executor，但结论须标为上层 Agent 的学习，不能称为通用 Qwen 独立操作能力。

## 希望证明什么，如何区分结论

| 待验证问题 | 必要对照 | 可以得出的结论 |
| --- | --- | --- |
| 开闭源差距出现在哪 | 当前 `q_only` 对同接口小样本 `astra_reference`；按任务/失败类型分层 | 未训练 Agent 的同接口差距及其主要表现；不能直接套用其他论文分数 |
| 少量专家是否有用 | 当前 `q_only` 对 `hybrid_plan`、`hybrid_diagnose`、`hybrid_both` | 规划/诊断工具在冻结 Qwen 上的增量，同时报告闭源调用成本 |
| Qwen 是否学会自主解决 | 原始 Qwen、SFT Qwen、局部训练 Qwen，**都关闭 Astra** | 模型本体的增量；离线代理任务只证明相应离线能力 |
| 是否只是更会求助 | 同一训练后 checkpoint 在专家关闭、固定可用、学习路由三种模式下比较 | 求助策略在同等调用上限下的增量，以及撤除专家后的保留能力 |
| 训练能否迁移到具身任务 | 未见任务/布局/seed 的独立 RoboDojo 原生评分 | 才能声称机器人闭环成功率或进度提高 |

模型训练产生新的条件名，例如 `qwen_sft_no_expert`、`qwen_local_rl_no_expert`、`qwen_router_rl_budget2` 和 `qwen_router_rl_expert_off`；名称在实现时随 checkpoint 与训练方案冻结。最后两个条件使用**同一个经过专家路由训练的 checkpoint**，仅在评测时开关 Astra，才构成有效的专家撤除对照。未训练六组与训练后组使用相同任务、观察、动作接口、安全守卫及物理预算；模型版本和额外训练数据另报。

开始收集训练标签前就划定开发、验证和锁定测试数据，并分别设计两种外推：**任务外推**要求测试 task ID 不出现在训练中；**布局外推**允许同一任务，但测试 layout ID 与 seed/episode 均不进入训练。第一阶段可以另报官方全任务成绩，但第二阶段不得依据锁定测试的失败案例选择训练样本、奖励权重或新增工具；若锁定集已被用于方案迭代，应另选未使用的布局/seed 并降低“未见任务”结论的范围。仅 seed 未见不能称任务泛化。

## 执行顺序与进入下一步的门槛

| 阶段 | 工作与产物 | 进入下一步的条件 |
| --- | --- | --- |
| A. 固定未训练基线 | 按现有 [RoboDojo 协议](mixed_agent_robodojo.md)运行六组；保留原生结果、轨迹、模型调用和动作拒绝原因 | Qwen/Astra 真实端点与 native score 接通；简单任务有可解释的有效动作。若全为 0，先排查接口与低层控制 |
| B. 数据与标签 | 只从**训练划分**的合法记录导出当前 RGB、公开状态、子任务起始图、决策、Astra 建议、工具回执和最终 native verdict；做人工/规则核验、去重和数据来源账本 | 样本能复现图像来源与动作顺序；任务外推组按 task ID 隔离，布局外推组按 layout/episode 隔离；无未来帧或隐藏评分进入模型输入 |
| C. 示范学习 | 对 Qwen 做小规模 SFT/LoRA，优先学习结构化计划、合法动作工具调用、回执理解和按 ID 回忆；教师建议可作为训练信号，不能自动当作真值 | 离线留出集上的格式有效率、任务状态理解和动作合法率有改善；记录教师调用与训练成本 |
| D. 可验证局部训练 | 在**有独立标准答案**的计划排序、工具 schema、子任务图像 ID、回执诊断和求助选择上尝试 RLVR 或等价优化；对错误调用和闭源调用收费 | 对比 SFT-only，留出集上正确率/校准改善，并在相同专家预算下减少无效求助；不据此宣称机器人成功率提高 |
| E. 可选闭环更新 | 只有 RoboDojo 环境、训练预算与安全守卫允许时，才用**训练划分**做短时物理 rollout，研究局部策略更新及信用分配 | 环境原生结果稳定、费用账本完整；不能把测试任务回灌训练 |
| F. 独立验收 | 冻结 checkpoint、提示、工具、专家预算和任务清单；在未见任务/布局上运行训练前后、专家开/关与小样本完整 Astra 参照 | 报告原生成功/进度、专家撤除、自主解决率、调用频率、全流程成本及失败分类 |

A 的环境接线与 B 的数据规范可以并行准备；**B–E 的性能结论必须由 F 验证迁移**。若只有静态数据，项目可以报告格式、空间识别或工具决策指标，但不可报告未运行的 RoboDojo 成功率。

## 首批可验证任务与奖励边界

首批离线样本来自当前 harness 的公开观察及回执，按 episode 保存 `task_id`、`layout_id`、`seed`、数据划分、模型/checkpoint、图像哈希与相机、子任务 ID、计划、动作工具和参数、动作合法/拒绝回执、Astra 调用原因及 token、原生终局结果。原生 hidden reward 只可在 episode 结束后用于训练划分的监督标签或分析，不能泄漏给在线策略。测试 episode 不得进入教师提示、Memory Bank、训练奖励或数据选择。

局部奖励必须来自独立可检查的答案：如 JSON/schema 是否合法、参数是否在控制范围、历史图像 ID 是否属于当前 episode、回执分类是否吻合日志、是否在规定条件下正确求助。可考虑 `正确性 − 无效工具惩罚 − 专家调用成本`，权重在验证集定好，不根据最终测试成绩回调。**教师文本偏好不等于客观可验证奖励**；空间定位与“当前任务是否完成”若无可信标注，先做人工审查/校准，不直接制造 RL 真值。轻量工具状态机适合训练流程和权限判断，不能模拟抓取接触、碰撞或物体动力学的真实后果。

闭源专家第一轮仍是当前代码中的**一次计划 + 一次诊断**。上传方案建议的空间定位、局部规划、状态核验是有价值的候选能力拆分，但必须先定义输入证据、结构化输出、可拒答和外部验证标准；任何新增工具都另开版本化矩阵，与原有条件分开汇报。专家不得看未来观察、测试答案或 RoboDojo 隐藏评分，不得向动作执行器发送命令，也不得把自己的“成功”说法覆盖环境 verdict。

## 全流程成本与报告规则

从数据获取/标注、教师和专家调用、图像处理、模型 SFT/RL、工具执行、失败重试，到最后 RoboDojo rollout，都记录资源用量；分别报告训练一次的固定成本与每个评测 episode 的增量成本。模型调用日志应保留输入/输出 token、延迟、成功/错误和单位价格是否已知；缺失价格只能标记未知，不能当作零。比较收益时同时展示**无专家自主成功率、同调用预算下成功率、实际闭源调用次数和最终原生成功率**。
